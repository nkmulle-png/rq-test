# SPEC123: `/test-a` JSON Endpoint

## Objective-ymusa-test-github  and also
kml
Add a new HTTP endpoint at `/test-a` that returns a JSON `"hello world"` payload. Purpose is a minimal smoke-test/demo endpoint (mirrors the existing `/health` route's role, but returns JSON instead of an HTML fragment).

**Target users:** internal developers verifying the TanStack Start server-route wiring on this deployment (HELIOS-99248 branch is CVE/deploy hardening work — this endpoint is a lightweight sanity check, not user-facing product functionality).

## Core Features & Acceptance Criteria

1. `GET /test-a` returns HTTP 200 with `Content-Type: application/json`.
2. Response body is JSON, e.g. `{ "message": "hello world" }`.
3. No authentication/authorization required (matches `/health`, which is public).
4. No other HTTP methods are handled — non-GET requests fall through to the framework's default (404/405 behavior), since only a `GET` handler is defined.

## Tech Stack

- **Framework:** TanStack Start (`@tanstack/react-start` 1.167.x) + TanStack Router file-based routing, on Vite 7 + `nitro` server target, deployed via Cloudflare Worker (`@cloudflare/vite-plugin`, `wrangler.jsonc`).
- **Route pattern:** file-based server routes using `createFileRoute(...)({ server: { handlers: { GET: ... } } })` — no React component needed for a pure API route.
- **Language:** TypeScript.

## Project Structure

New file: `src/routes/test-a.ts`

The route tree (`src/routeTree.gen.ts`) is auto-generated by the TanStack Router Vite plugin (`@tanstack/router-plugin`) on `vite dev` / `vite build` — it will pick up the new file automatically; no manual edit to `routeTree.gen.ts`.

## Code Style

Follow the existing minimal route style seen in `src/routes/health.tsx:1-2` (terse, no extra abstraction for a trivial route). Match repo formatting (Prettier config in `.prettierrc`, ESLint config in `eslint.config.js`).

```ts
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/test-a")({
  server: {
    handlers: {
      GET: () => Response.json({ message: "hello world" }),
    },
  },
});
```

## Testing Strategy

- No test framework (Jest/Vitest) is currently configured in this repo (`package.json` has no `test` script).
- Verification is manual: run `bun run dev` (or `npm run dev`), then `curl http://localhost:<port>/test-a` and confirm a `200` with JSON body `{"message":"hello world"}`.
- Out of scope: adding a test framework to the repo as part of this change.

## Boundaries

- **Always:** keep the route unauthenticated and side-effect-free (no DB/Supabase calls) since it's a smoke-test endpoint.
- **Ask first:** if this endpoint should later be wired into CI/CD health checks or the Cloudflare deployment's readiness probe.
- **Never:** put secrets, environment values, or internal diagnostic data in the response body.
